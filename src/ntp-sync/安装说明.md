# NTP Time Sync 安装与使用说明

> 版本 1.2.0 ｜ 适用平台：**Windows 7 SP1 及以上**（32 位 / 64 位）
> 时间基准：**中国标准时间 UTC+8** ｜ 同步方式：NTP/UDP，被封自动降级 TCP

---

## 0. 先看这里（30 秒决定怎么装）

| 你的情况 | 用哪个文件 | 怎么装 |
|---|---|---|
| 想省事，装完开机自动对时 | `ntp_sync_setup.exe` | 双击 → 下一步 → 装完就好 |
| 不想装、拷到 U 盘就用 | `ntp_sync_win7_x86_py37.zip` | 解压 → 双击 `install_service.bat` |
| 只想临时对一次时间 | 上面任意一个里的 `sync.bat` | 双击，弹 UAC 点「是」 |

**装之前只需确认一件事**：机器已安装 **KB2999226（Universal C Runtime）** 或 **VC++ 2015-2019 运行库**。
没装的话程序自带的 `python.exe` 起不来，会一闪而过。装过 VS 或较新的软件一般都已有。

下载后如果提示「文件被锁定/来自网络」，右键文件 → 属性 → 勾选「解除锁定」→ 确定。

## 1. 方式一：安装包（推荐）

### 1.1 安装步骤

1. 把 `ntp_sync_setup.exe` 拷到 Win7 机器上（U 盘、局域网共享都行）。
2. **右键 → 以管理员身份运行**（或直接双击，UAC 弹窗点「是」）。
3. 向导是英文的，一路点：
   - `Next` → 选择安装目录（默认 `C:\Program Files (x86)\NtpSync`，64 位系统；32 位系统是 `C:\Program Files\NtpSync`）→ `Next`
   - `Install` → 等进度条走完 → `Finish`
4. 安装过程会自动做三件事，**不需要你手动操作**：
   - 把系统时区设为 `China Standard Time`（UTC+8）
   - 注册服务 `NtpSync` 并**立即启动**
   - 创建开始菜单文件夹 `NTP Time Sync` 和桌面快捷方式 `NTP Time Sync`

### 1.2 装完会得到什么

| 位置 | 内容 |
|---|---|
| `C:\Program Files (x86)\NtpSync\` | 程序本体 + 内置 32 位 Python 运行时 |
| `service.ini` | 配置文件（同步间隔、日志轮转，可改） |
| `service.log` | 服务日志（自动轮转） |
| 开始菜单 `NTP Time Sync` | `Sync clock now`（手动同步）、`Check clock`（只检查）、`Service log`（打开日志）、卸载 |
| 服务管理器里的 `NtpSync` | 启动类型 **自动**、登录身份 **LocalSystem** |

### 1.3 静默安装（批量装机用）

```cmd
ntp_sync_setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
```

## 2. 方式二：免安装绿色版

1. 把 `ntp_sync_win7_x86_py37.zip` 解压到**固定目录**，例如 `D:\NtpSync`。
   - 路径带空格、中文都行，**但别放桌面/下载文件夹后随手删**——服务启动命令是指向这个路径的，删了服务就启动失败。
2. **右键 `install_service.bat` → 以管理员身份运行**。
   它会以 1800 秒（30 分钟）间隔注册并启动服务，屏幕会显示 `service state: RUNNING`。
3. 卸载时运行 `uninstall_service.bat`（同样要管理员）。

> 绿色版和安装包**功能完全一样**，区别只是安装包多了开始菜单、桌面快捷方式和标准卸载入口。

## 3. 装完怎么验证（别跳过这步）

### 3.1 看服务状态

```cmd
cd /d "C:\Program Files (x86)\NtpSync"
python.exe ntpsvc.py status
```

正常输出长这样：

```
service   : NtpSync
state     : RUNNING
accepts   : 0x5
exit code : 0
log file  : C:\Program Files (x86)\NtpSync\service.log
log rotate: 1048576 bytes x 5 backups
  ...\service.log        410 bytes
```

`state: RUNNING` + `log rotate` 那两行有内容，就说明服务和日志轮转都就位了。

### 3.2 看日志（最直观）

```cmd
type service.log
```

正常内容类似：

```
2026-11-13 08:24:45,177 [INFO] worker started (interval=600s max_skew=7200s tolerance=0.5s ...)
2026-11-13 08:24:45,180 [INFO] system time zone is UTC+8 (China Standard Time)
2026-11-13 08:24:49,202 [INFO] NTP/UDP OK: 10 usable samples
2026-11-13 08:24:49,203 [INFO] clock already within 0.5 s (+0.011 s via ntp/udp), next check in 600 s
```

几行都认一下：

- `worker started` —— 服务起来了
- `system time zone is UTC+8` —— 时区正确
- `NTP/UDP OK` —— UDP 通，走的是主通道
- 如果出现 `NTP/UDP unusable ... falling back to TCP/HTTP Date` —— **不是错误**，说明 UDP 被封了，已经自动换 TCP，功能照常

### 3.3 手动对一次（只检查 / 真写入）

```cmd
python.exe ntp_sync.py              :: 只检查，不动系统时间（默认行为）
python.exe ntp_sync.py --apply      :: 真写入，需要管理员命令行
```

或者直接双击开始菜单里的 `Sync clock now`，它会自己弹 UAC 提权。

### 3.4 验证「真的是开机就同步，不是进桌面才同步」

这是这次改造的重点，验证方法：

1. 装好后**重启**电脑。
2. **停在登录界面不要登录**，等 1 分钟。
3. 登录后打开 `service.log`，看第一行时间戳——它应该**早于**你登录的时间（通常早几秒到几十秒）。

服务是 `AUTO_START` + `LocalSystem`，由系统在 boot 阶段拉起，跟用户登录完全无关；日志第一行时间戳就是证据。

## 4. 改配置：`service.ini`

安装目录下的 `service.ini`，改完**重启服务**生效：

```cmd
python.exe ntpsvc.py stop
python.exe ntpsvc.py start
```

```ini
[sync]
interval = 1800        ; 每隔多少秒校准一次（默认 1800 = 30 分钟）
max_skew = 7200        ; 运行期偏差超过这个值就拒写，防大跳变（默认 7200 = 2 小时）
tolerance = 0.5        ; 偏差小于这个值就不动时钟（默认 0.5 秒）

[log]
max_bytes = 1048576    ; 单个日志文件超过多少字节就轮转（1 MiB；0 = 关闭轮转）
backups = 5            ; 保留几份历史日志（service.log.1 ~ .5）
```

**关于 2 小时护栏**：这是防止时间一次跳掉一两天/十几天，把 TLS 证书、域认证、计划任务全打挂。
注意例外：**开机后的第一次同步不受此限制**（CMOS 掉电差几年也能修回来），只有运行期间的周期校准才受 2 小时限制。

**关于日志轮转**：默认 1 MiB × 5 份，最坏占 6 MiB 左右。30 分钟一行，1 MiB 够存半年以上。
不用管它，它自己会转；`status` 能看到当前和历史文件的大小。

## 5. 时间来源与两个安全设计

### 5.1 来源优先级

1. **NTP v4 / UDP 123** —— 默认中国源优先：`ntp.ntsc.ac.cn`（国家授时中心）、`ntp.aliyun.com`、`time1.cloud.tencent.com`、`cn.pool.ntp.org`，再加 `time.windows.com`、`pool.ntp.org` 兜底。
2. **UDP 被封时自动降级 TCP** —— 读网站的 HTTP 响应头 `Date`（这是普通 HTTP 请求的响应头，不是抓包工具），并按 `Age` 头修正 CDN 缓存时间。默认 `http://www.baidu.com` → `https://www.baidu.com` → `https://www.qq.com`。

> 注意：明文 `http://` 排在第一位是刻意的。系统时间错到 2009 年时，HTTPS 证书有效期必然覆盖不到当前时间，严格校验一定失败，明文通道不受时间影响。

### 5.2 证书校验默认关闭

`--verify-tls` 才是开启。默认关闭的原因：时间错 → 证书校验失败 → 拿不到 `Date` → 时间永远修不对，这是个死锁。程序只读响应头里的 `Date`，不传输任何数据。

### 5.3 时区

写入系统时间用的是 **UTC**（API 要求），同时把 Windows 时区设为 `China Standard Time`。
所有报告和日志以**北京时间为主、UTC 为辅**显示：

```
2026-11-13 08:26:14.106 UTC+8  (2026-11-13 00:26:14.106 UTC)
```

如果日志里出现 `system time zone is UTC+6, expected UTC+8; run: python ntpsvc.py set-tz`，说明时区不对，执行：

```cmd
python.exe ntpsvc.py set-tz
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 bat 黑框一闪就没 | 缺 KB2999226 / VC++ 运行库 | 装 Universal C Runtime 后重试 |
| `service.log` 里全是 `UDP/123 may be blocked` | 防火墙/运营商封了 UDP 123 | 正常，已自动走 TCP，不用管 |
| 服务装了但 `state: STOPPED` | 安装目录被移动/删除，服务路径失效 | 重新运行 `install` 或安装包修复 |
| 时间没变 | 偏差小于 `tolerance`（0.5s），按设计不动 | 想强制就 `--apply --tolerance 0` |
| 提示 `skew guard refused` | 运行期偏差超过 `max_skew`（2 小时） | 确认时间真错得离谱后，手动执行 `python.exe ntp_sync.py --apply --force` |
| win7 双系统，切回 Windows 时间差 8 小时 | Linux 把硬件时钟写成了 UTC | 用 `--set-timezone` 确保时区是 UTC+8，或让 Linux 用 `localtime` |
| 卸载后服务还在 | 非正常卸载（直接删目录） | 管理员运行 `python.exe ntpsvc.py uninstall` |

## 7. 卸载

**安装包版**：控制面板 → 程序和功能 → `NTP Time Sync` → 卸载。
会先停服务、删服务，再删目录（含 `service.log`、`service.log.1~5`、`service.ini`、快捷方式），无残留。

**绿色版**：

```cmd
:: 管理员命令行，在程序目录下
python.exe ntpsvc.py uninstall
```

然后直接删整个文件夹。

## 8. 命令行速查

### `ntp_sync.py`（对时主程序）

| 参数 | 作用 |
|---|---|
| （不加参数） | 只检查，打印偏差，**不改系统时间** |
| `--apply` | 真正写入系统时钟（需管理员） |
| `--elevate` | 非管理员时自动弹 UAC 提权重启自己 |
| `--force` | 允许超过 2 小时的大跳变（危险） |
| `--tolerance SEC` | 偏差小于此值不动时钟（默认 0.5） |
| `--max-skew SEC` | 偏差大于此值拒绝写入（默认 7200） |
| `--server HOST` | 指定 NTP 服务器（可重复，覆盖默认列表） |
| `--http-url URL` | 指定 TCP 回退源（可重复） |
| `--timeout SEC` / `--samples N` | 单次超时（2.0）/ 每源采样次数（2） |
| `--set-timezone` | 把系统时区设为 UTC+8 |
| `--verify-tls` | 开启 TLS 证书校验（默认关） |
| `--log-file PATH` | 写日志到这个文件（自动轮转） |
| `--log-max-bytes N` / `--log-backups N` | 轮转阈值（1 MiB）/ 保留份数（5） |
| `--json` | 输出 JSON，方便接监控脚本 |
| `--self-test` | 离线逻辑自检（11 项，不联网） |
| `--selftest-apply` | 真写测试：注入小偏差 → 同步 → 自动还原 |
| `--version` | 版本号 |

### `ntpsvc.py`（服务管理）

| 子命令 | 作用 |
|---|---|
| `install [--interval N] [--log-max-bytes N] [--log-backups N]` | 注册并启动服务（需管理员） |
| `uninstall` | 停止并删除服务（需管理员） |
| `start` / `stop` | 启动 / 停止服务 |
| `status` | 查看状态、日志路径、轮转配置与文件大小 |
| `set-tz` | 时区设为 UTC+8 |
| `debug` | 前台跑同步循环，Ctrl+C 退出（排错用） |
| `run` | 服务入口，SCM 专用，**不要手动执行** |
